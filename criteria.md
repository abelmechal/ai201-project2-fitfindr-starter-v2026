# Acceptance criteria - FitFindr

Five criteria that say what "working" means for this agent, written before
the unit 4 test results.

---

## 1. A matching query completes all three tools

Given a query that matches at least one listing, the agent completes all three
tool calls and returns a fit card - in at least 4 of 5 tries.

**Why this target:**
The search tool uses keyword overlap, so some natural phrasings may miss an
item even when a human would recognize the match. If the query uses words that
are actually in the listing, the loop should usually complete all three tools.

---

## 2. An impossible query stops before the second tool

Given a query that matches no listings, the agent stops before calling
`suggest_outfit` and returns a message naming what to change - 5 of 5 tries.

**Why this target:**
This path is deterministic because `search_listings` returns an empty list and
the loop branches on that exact value. It should never call the model tools with
no item.

---

## 3. State carries the selected item forward

For at least 4 of 5 matching queries, `session["selected_item"]["id"]` is the
same item id that appears in `session["outfit_suggestion"]`.

**Why this target:**
The item found by search has to be the item styled by the next tool. I chose 4
of 5 because the outfit suggestion is model-written text, so wording can vary,
but the prompt asks it to name the item id.

---

## 4. Fit cards include the important listing details

For at least 4 of 5 completed runs, the fit card mentions the item, the price,
and the platform.

**Why this target:**
The exact caption wording can change because it is generated by a model, but a
useful thrift caption should still tell someone what the item is, what it costs,
and where it is listed.

---

## 5. Search respects the price ceiling

For 5 of 5 searches with a max price, every returned listing has `price` less
than or equal to `max_price`.

**Why this target:**
Price filtering is not subjective and happens before generation. If a user asks
for something under a budget, returning an item above that budget is a tool bug,
not a model variation.
